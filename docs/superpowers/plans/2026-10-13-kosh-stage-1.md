# kosh stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** kosh, deployable with its Helm chart into a Kubernetes cluster, where `ssh` and `iroh-ssh` both land an accepted key in a k9s-like terminal UI for that cluster: the browser over every resource, 27 typed kinds, describe, YAML, logs, and the actions that change the cluster, with read-only keys that can change nothing and read no Secret.

**Architecture:** One Go program, one process in the pod. A TCP listener and an iroh endpoint (ALPN `/iroh/ssh`) both hand connections to one SSH server (wish v2), which checks the key list and runs one Bubble Tea v2 program per session. The program sees the cluster only through the `kube.Session` interface, whose implementation holds the process-wide informers and is the one place a grant is checked. Renderers are pure functions from an object to a table row.

**Tech Stack:** Go 1.26, `github.com/tmc/go-iroh` v0.3.0, `charm.land/wish/v2` v2.0.5 over `charm.land/ssh` v0.4.3, `charm.land/bubbletea/v2` v2.0.10, `charm.land/lipgloss/v2`, `charm.land/bubbles/v2`, `k8s.io/client-go` and `k8s.io/kubectl` v0.37.1, `urfave/cli/v2`, controller-runtime's `envtest` for tests, Helm, Nix with `draganm/gonixgo`.

**Spec:** [`docs/superpowers/specs/2026-10-13-kosh-stage-1-design.md`](../specs/2026-10-13-kosh-stage-1-design.md). The plan argues from it. Every implementer reads the sections their task names, and §2 (terms) and §17 (packages) whatever the task.

## Global Constraints

Every task's requirements include these.

- **Module** `github.com/fables-for-robots/kosh`. Packages at the top level of the module. **No `internal/` packages**, anywhere.
- **Command line** is `github.com/urfave/cli/v2`.
- **`go.mod` is pinned by Task 1** and holds every dependency the plan uses (`cli/pin.go` keeps them there). A task does not run `go get` or change a version. A task that finds it needs a module that is not there stops and says so in its report.
- **kosh starts no other process.** No `os/exec` outside tests and scripts.
- **The contract is code.** Task 1 puts the exported types, interfaces and function signatures of every package into the repository, with their documentation. A task fills in its package behind those signatures. It does not change an exported signature, a documented behaviour or another package's files; when the contract is wrong for what the task has to do, the task stops and reports that instead of working around it.
- **A task changes only the files its task file lists**, plus new test data beside them.
- **Tests:** written first and seen to fail (TDD). `go test -race ./<package>/...` passes, `go vet ./...` and `gofmt -l .` are clean, and `go build ./...` passes for the whole module, before a task is reported done. No test needs the network, except those of Task 19. Time in tests comes from a clock the test controls or from intervals of milliseconds; no test sleeps for seconds to wait for something that can be waited for.
- **No data races.** Everything a session shares with another, or with a background goroutine, is guarded.
- **Text from the cluster is never trusted to the terminal.** Whatever the UI draws that came from the API (cells, YAML, descriptions, log lines, errors) goes through `tui.clean` first (Task 11).
- **Documentation:** every exported identifier has a doc comment in the manner of the contract's: plain sentences that say what it does and what it does when things go wrong.
- **k9s as reference.** k9s at commit `8f29fba` is cloned at `/private/tmp/claude-502/-Users-dragan-fables-for-robots/25996946-215e-4a11-ba9e-574cacaa75eb/scratchpad/k9s-src/repo` (read-only). kosh's code is written for kosh. A file whose logic follows a file of k9s closely says so in a comment at its top (`// Derived from k9s's internal/render/pod.go, Copyright Authors of K9s, Apache-2.0 (see LICENSES/Apache-2.0.txt); changed for kosh.`); `NOTICE` credits k9s, and `LICENSES/Apache-2.0.txt` holds the licence's text.
- **Licence** BSD-3-Clause (it was LGPL-3.0-only while stage 1 was built; changed at its release, on the owner's word).
- **Commits:** one or more per task, each leaving the module building. The message is `Area: a sentence that says what is now true`, as `Keys: a line with an unknown option gives no access`, and ends with these two trailer lines:

  ```
  Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_012Y76zZnbm2mtUzXqHDuySf
  ```

- **Leave no binaries behind.** A binary a task builds (`go build -o`, `go test -c`, a Nix `result`) is removed before the task is reported done.

## Review Focus

What the spec implies and no feature test would otherwise reach, most likely to bite first. Each line names the task whose tests pin it.

1. **Escape sequences and control characters in cluster data.** A log line, an annotation, an event message or an environment value can hold terminal escape sequences; drawn raw they rewrite the user's screen or worse. Expected: they are shown harmless. Pinned in Task 11 (`clean`, and the table), Task 12 (text views) and Task 13 (logs).
2. **A terminal of any size, and a table of any length.** A window of 0 by 0, 1 by 1, or one row short of the minimum, and a table of 5000 rows. Expected: no panic, no line wider than the window, the "too small" line below 80 by 12. Pinned in Task 11.
3. **A peer that says nothing, or something that is not SSH.** A TCP connection that sends no byte, one that sends garbage, one that closes mid-handshake; an iroh connection that opens no stream, or opens one and writes nothing. Expected: each is closed by its deadline, holds no handshake slot after that, and leaks no goroutine. Pinned in Task 15 and Task 4.
4. **A log line without an end.** A container that writes megabytes without a line feed, or binary. Expected: memory stays bounded, the line is cut at a limit and marked. Pinned in Task 9.
5. **A key list as people write them.** CRLF line ends, a byte order mark, a last line without a line feed, a line of 100 kB, a comment with spaces, the option in capitals. Expected: every good key is accepted, nothing is fatal, and nothing that is not understood grants access. Pinned in Task 2.

**How the waves are built.** The tasks of a wave touch disjoint files and are built side by side, each in a git worktree of its own on a branch `task-NN` cut from `stage-1`, by a fresh implementer, and reviewed by a fresh reviewer before its branch is merged into `stage-1`. A wave's merges are in before the next wave is cut. That is what the pinned `go.mod` and the contract in code are for: nothing two tasks of a wave both write.

## Departures

What was built differs from what this plan and its task briefs said in the
places below. Each was decided while the plan was carried out; the ledger
beside the task files (`2026-10-13-kosh-stage-1/ledger.md`) has each
decision with its reason and what it costs if it was wrong. Where the spec
itself was amended, the section is named.

### How it was carried out

| The plan said | What was done | Why |
|---|---|---|
| One task at a time | Waves of tasks in parallel, each in a git worktree of its own, merged into `stage-1` after its review | The tasks own separate packages behind a contract that was compiled first |
| A task starts from reviewed work | Later waves were cut from integration branches that held tasks still in review; their final commits were merged in afterwards | Waiting for every review would have idled most of the work; each such base built and passed its tests |
| Commits end with `Co-Authored-By: Claude Fable 5.1` | A commit carries the trailer of the model that wrote it | The trailer is attribution and should be true |
| Fix rounds 4 and 5 go to a fresh implementer on a more capable model | Task 10's round 5 went to the same implementer | The open point was caused by the controller's own instruction and the fix was prescribed exactly |

### Transports and the SSH server

| The plan said | What was built | Why |
|---|---|---|
| mDNS through go-iroh's `iroh/mdns` | An announcer of kosh's own, `irohnet/peermdns.go` (spec §4.2) | The probe found that `iroh-ssh` cannot find go-iroh's: other base32 names, no TXT record |
| Every address of the machine is announced | No tunnel, loopback or link-local address; of bridges only `docker0` and `br-<12 hex>` are left out by name | A tunnel address in the announcement made connections time out |
| Nothing about unicast mDNS questions | Only questions sent to the group are answered, and only interfaces whose addresses are announced are joined | RFC 6762 §11 |
| A connection's `Close` closes the iroh connection | It gives the peer 2 seconds to close first, in a goroutine | Closing at once can cut off the SSH exit status |
| The UI runs through wish's Bubble Tea middleware | kosh runs the program itself with wish's options (spec §5) | The middleware swallows the program's error and leaves it listening for SIGTERM |
| Nothing about idle connections or limits | A connection without a session is closed after 5 seconds; 20 authentication tries; at most 10 session channels per connection and 16 connections per key (spec §5) | Connections lingered after a clean exit; `iroh-ssh` lets `ssh` offer the agent's keys first; each session channel lets its client make the server hold 2 MiB |
| Certificates in the key list were not mentioned | A certificate gives no access; a comment that begins with `read-only` rejects its line (spec §6) | kosh checks no certificate's validity; `KEY read-only guest` would have been a full key |

### Cluster data and actions

| The plan said | What was built | Why |
|---|---|---|
| Typed shared informers | One shared informer per kind over the dynamic client, typed by a transform (spec §8.1) | A typed informer factory cannot stop one kind |
| A table whose list fails shows the error | A table that has synced keeps its rows and is marked stale; the error is for a cache that never had its first list | Spec §8.5 |
| References are checked against path characters | A reference must match an allow-list and be a resource that discovery found | A deny-list let the resource `.` through |
| `Update` cleans and applies the edited YAML | It parses and sends the text exactly as written, after counting its documents with the same parser; more than one document is refused | Re-encoding changed folded scalars the user had not touched |
| The log line of a failed action carries the error | It carries the API error's reason and code only | A webhook can put any text, an edited Secret's value included, into a status |
| Nothing about API warnings | Their text is discarded; a debug line counts them | client-go writes them to standard error |
| Drain as k9s does | It waits 5 seconds between retries of a refused eviction, as kubectl does; its output is kept to 16 KiB | The contract says "as kubectl drain does" |
| `kube.RESTConfig` takes one path; no getter for the version | A value with several paths is read as kubectl reads `KUBECONFIG`; `Cluster.Version()` | Found while wiring `kosh serve` |

### Renderers

| The plan said | What was built | Why |
|---|---|---|
| A pod's STATUS as k9s's Phase | As kubectl's `printPod` where the two differ (Terminating over an init status, NotReady, SchedulingGated, sidecars), also for a deleted pod that has ended | The brief said STATUS is what kubectl prints and named the wrong function of k9s |
| A deployment's health paraphrased | k9s's colorer: Pending when it wants no replicas, an error when it wants some and has none | The brief said to read k9s for it |
| A job is Completed when its successes reach its completions | When it says so (completion time or its Complete condition) | A work queue has no count to reach |
| ConfigMap DATA as k9s | `Data` plus `BinaryData`, as kubectl | It is the number of entries the object has |
| A node without a Ready condition | STATUS `Unknown`, as kubectl | k9s shows an empty cell through dead code |
| A cordoned node is Pending | It also shows k9s's reason in VALID | The brief was silent on VALID |
| CPU/RL and MEM/RL with units | As k9s prints them (`100:500`, memory in MiB) | "As k9s prints them" was the instruction |
| A CRD's VALID "as k9s's diagnose" | k9s's reasons plus "not established" | Both are wanted |
| Rules as k9s shows them | A rule limited by `resourceNames` is a row of its own, `resource[name,…]`; no VALID column | k9s overstates what such a role allows |

### The UI

| The plan said | What was built | Why |
|---|---|---|
| The table's column cursor on `h`/`l` and the arrows | The arrows only | `l` is the Logs key |
| The editor cleans the YAML it opens | It refuses to open an object whose YAML cleaning would change, and sends exactly what was read plus what was typed | Cleaning silently changed data on save |
| The drain dialog takes any timeout | Above zero and at most one hour | A drain without a deadline cannot be cancelled from the UI |
| `c` in a log copies what the buffer holds | It copies the lines that are shown (under a filter, the filtered ones) | "As it is drawn", and as k9s |
| The prompt and the editor take paste keys | Paste is disabled in every text input | The library's paste reads the clipboard of the machine kosh runs on |

### Commands, build and release

| The plan said | What was built | Why |
|---|---|---|
| Errors begin `kosh serve:` / `kosh id:` | They begin with what failed; `main` prints `kosh: ` before them | A user read `kosh: kosh serve: …` |
| A stop waits 10 seconds for the sessions | One deadline of 10 seconds covers the whole stop; a stop asked for during the start returns cleanly; a second signal kills the process | Spec §18 says 10 seconds in all |
| A listener's error ends `kosh serve` | So does a listener that ends by itself without an error | A kosh that runs on without one transport and says nothing is worse than a restart |
| client-go's logging goes to kosh's log at debug | Only its V(0) lines and errors | At higher verbosity client-go logs request bodies |
| The development shell carries kube-apiserver and etcd | `scripts/envtest-assets.sh` fetches them (spec §16) | nixpkgs has no kube-apiserver for a Mac |
| The image check looks for a shell | It compares the image's whole content with a list; `bin/kosh` is the only program | "No shell and no other program" needs an allowlist to be shown |
| A tag `v*` releases | A first job refuses a tag that is not `vMAJOR.MINOR.PATCH[-pre]` before anything is published | Helm refuses such a version only after the images are pushed |

### What the end-to-end run and the review of the whole branch changed

These came after every task was built: from kosh run in a real cluster with the real `ssh` and `iroh-ssh`, and from three reviewers reading across packages for the first time.

| The plan said | What was built | Why |
|---|---|---|
| A query names a resource and a namespace | The session refuses a namespace that is not a name and a resource that discovery did not make, and the UI refuses such a word at the prompt; `:pods all` and `:pods -A` mean every namespace | A word typed as a namespace reached the API path of a generic table's list, and with it the API server's proxy, for any key |
| An action runs with the caller's context | It also ends when its session does, and is refused once the session has ended | A confirmed delete or a drain went on after its key had left the list |
| A session channel is handed to the SSH library | Its requests are filtered first: `env` within a bound, the few kosh uses, nothing else | The library keeps every `env` request and agrees to agent forwarding |
| A key removed from the list loses its sessions | And its connections | The connection kept its place and could go on opening channels |
| The comment guard looks at the first word | `read-only`, `readonly`, `read_only` or `read only` anywhere in a full key's comment rejects the line (spec §6) | `(read-only) guest` and `guest read-only` gave full keys |
| A refusal of a read-only key is logged | Also for the reads of a Secret, which logged nothing | Spec §13 |
| Every connection's end is logged at info | A connection that never sent a byte is logged at debug | The kubelet's probes were most of the log |
| A stop closes the listeners and tells the sessions | It tells the sessions first, and a closed iroh connection is given its two seconds | Over iroh the listener's close cut every session before it was told |
| The first QUIC key update of a connection is the library's affair | kosh postpones the one its side starts to the regular interval, through a setting of the library's internal package | The library's key-update check is wrong for connections with several paths, and cut one direct connection in thirteen from a client on iroh 1.x |
| The announcer joins every multicast interface | Only those that have an address it announces | A node has many, and a socket has 20 memberships |
| A dialog is laid over the body | Over the whole screen; it shows as many names as fit and always its buttons; on a screen too small for it the action is refused | At 80 by 24 a delete of 12 marked pods had no visible buttons |
| An error is a line of the flash | It is wrapped onto up to four lines and stays until a key is pressed; the editor's stays until the next save; a table's fills its body | A line cut at 80 columns for five seconds could not be read |
| The header shows what fits | Only whole columns of hints, and `<?> Help` before a second column of shortcuts | At 80 columns every header line ended in `…` |
| The stack of views grows as the user goes | At most 32 views; a view that is covered stops reading until it is on top again | A user could make kosh hold and re-read any number of tables |
| `clean` removes control characters | Also the bidirectional controls | A name from the cluster could be drawn reordered |
| A log view keeps 5,000 lines | And at most 16 MiB | 5,000 lines of 64 KiB are 320 MB |
| The editor opens any object under its line limit | At most 1,000 lines and 48 KiB, and its text may grow to 64 KiB; inputs elsewhere take 1,024 characters | The library's text area costs in proportion to the whole text on every key |
| The help fits the screen | It lists every key, and scrolls sideways when it does not fit | Spec §10.2 says every key |
| AGE of a generic table is the server's cell | Its sort key is the object's creation time, and cells that are durations sort by their value | The server sends ages as text |
| The ClusterRoleBinding is named for the release | For the release and its role; the host network only with iroh on; nothing of iroh rendered with iroh off | `helm upgrade` could not change the role |
| The image holds kosh, its certificates and its user | And `/licenses`; the files that derive from k9s carry the notice the Apache licence asks for, and its text is in `LICENSES/` | Apache-2.0 §4 |
| The standard `log` package was not mentioned | Its lines, and those of libraries that log through the default `slog`, go into kosh's log at warn level, cut to 1 KiB | A QUIC library's warning arrived outside kosh's format |
