## Rulings before the first dispatch

- Ruling: the tasks of a wave are built side by side, each by its own implementer in its own git worktree, although the skill says never to dispatch implementers in parallel — the plan was written for it (disjoint files, go.mod pinned, the contract compiled), and the user asked for the shortest time to a correct result — if wrong: merge conflicts between task branches, which show at merge and cost a rebase.
- Ruling: a task's brief is its file under `docs/superpowers/plans/2026-10-13-kosh-stage-1/`, complete in itself, instead of an extract of the plan made by `task-brief` — the plan keeps its tasks in files of their own — if wrong: nothing; it is the same text.
- Ruling: task briefs give behaviour and tests, not finished code, except for the contract, which is code in the repository — a stage of this size written out as code in a plan would be the implementation written twice — if wrong: an implementer builds something other than intended, which the task review is there to catch.
- Ruling: the briefs of waves 2 to 4 are written while wave 1 is built, against the code wave 1 produces — the user's practice in great-machine was a plan against the code that exists — if wrong: a later brief contradicts an earlier one; the scan below is repeated for each wave.
- Ruling: the plan was not handed to the user for review before execution — they answered the spec review with "looks good, go and implement it" — if wrong: rework of whatever in the plan they would have changed.
- Ruling: execution is subagent-driven — the user chose it for great-machine over the recommendation of native execution — if wrong: more tokens than native execution.
